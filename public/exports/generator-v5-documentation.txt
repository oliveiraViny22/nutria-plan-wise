================================================================================
                         1. VISÃO GERAL
================================================================================

O Gerador v5.17 é responsável por criar planos alimentares personalizados com 
base no perfil do usuário. Utiliza um pipeline de convergência para garantir 
que os planos atendam a contratos nutricionais rigorosos.

FLUXO PRINCIPAL:
  buildMeal() → scale() → boostCarbs() → validateNutritionalContracts() → save()

CARACTERÍSTICAS:
  - Múltiplas opções por refeição (baseado no plano)
  - Bloqueio de alimentos gordurosos
  - Proteção de proteína mínima
  - Injeção agressiva de carboidratos para bulk
  - Validação estrita antes de salvar

================================================================================
                     5. PIPELINE DE GERAÇÃO
================================================================================

--------------------------------------------------------------------------------
ETAPA 1: CARREGAMENTO DE DADOS
--------------------------------------------------------------------------------

  loadData(supabase):
    → Carrega meal_templates (templates ativos)
    → Carrega meal_template_roles (ordenado por sort_order)
    → Carrega meal_role_food_categories (categorias por role)
    → Carrega meal_anchor_foods (âncoras ativas com alimentos)
    
  filterFoods(allFoods, avoided, restrictions):
    → Remove alimentos evitados
    → Aplica restrições (vegano, low carb, lactose, glúten, pescetariano)
    → Remove receitas e alimentos não canônicos

--------------------------------------------------------------------------------
ETAPA 2: CONSTRUÇÃO DE REFEIÇÕES (buildMeal)
--------------------------------------------------------------------------------

  Para cada tipo de refeição:
  
  1. ÂNCORAS PRIMEIRO:
     → Filtrar âncoras não usadas, não gordas, não similares
     → Aplicar limite de proteína em lanches
     → Aplicar boost de carbs para bulk (+25%)
     
  2. ROLES OBRIGATÓRIOS:
     → Preencher roles is_required com alimentos filtrados
     → Respeitar limites de categoria
     → Priorizar preferências do usuário (80% chance)
     
  3. ROLES OPCIONAIS:
     → Completar até atingir target de itens por refeição
     → Mesmas regras de filtragem
     
  4. GARANTIA DE PROTEÍNA MÍNIMA (v5.12):
     → Se proteína < mínimo, aumentar porção de alimento proteico
     → Ou adicionar alimento proteico se necessário

--------------------------------------------------------------------------------
ETAPA 3: ESCALONAMENTO (scale)
--------------------------------------------------------------------------------

  Objetivo: Atingir meta calórica respeitando proteína

  v5.15 - REDUÇÃO ATIVA DE PROTEÍNA:
    Se proteína > 95% MAS calorias < 60%:
      → Reduzir porções de alimentos proteicos para 70% da meta
      → Libera espaço para escalar carboidratos

  ESCALONAMENTO ITERATIVO (5-8 iterações):
    → Calcular fator de escala geral
    → PROTEÇÃO: Se proteína excederia 110%, não escalar proteicos
    → COMPENSAÇÃO: Escalar carboidratos até 2.5x para compensar
    → Para bulk com alta demanda: expandir limites +50%

  v5.17 - FALLBACK DE INJEÇÃO CALÓRICA:
    Se após scaling: calorias < 88% E proteína > 98%:
      → Detecta "travamento" (stall)
      → Injeta carboidratos agressivamente (limite 2x)
      → Adiciona até 100g por item de carb

--------------------------------------------------------------------------------
ETAPA 4: BOOST DE CARBOIDRATOS (boostCarbs)
--------------------------------------------------------------------------------

  Ativado quando: carbs < threshold mínimo (80% bulk, 90% outros)

  PASSO 1 - BOOST INICIAL:
    → Aumentar alimentos com >15g carbs/100g
    → Cap em 50% de aumento por item (150% para bulk)
    → Expandir limites de categoria se necessário

  PASSO 2 - GARANTIR PISO:
    → Loop de convergência (5 tentativas)
    → Reduzir calorias de não-carbs se exceder 110%
    → Completar carbs até atingir piso

--------------------------------------------------------------------------------
ETAPA 5: VALIDAÇÃO E SALVAMENTO
--------------------------------------------------------------------------------

  validateNutritionalContracts():
    → Validar TODAS as opções de refeição
    → Verificar cada contrato do GENERATOR_CONTRACT
    → Usar threshold de carbs baseado no objetivo
    
  SE INVÁLIDO (C1):
    → Retorna erro 400 com código NUTRITIONAL_VALIDATION_FAILED
    → Plano NÃO é salvo
    
  SE VÁLIDO:
    → Arquiva planos antigos
    → Insere novo diet_plan
    → Insere meals, meal_options, meal_option_foods
    → Incrementa usage do usuário
