================================================================================
                         1. VISÃO GERAL
================================================================================

O Rebalanceador v2 é responsável por ajustar planos alimentares existentes
para atingir metas nutricionais específicas. Utiliza uma pipeline de 5 etapas
com precisão de ±1g e threshold de otimização de 3%.

FLUXO PRINCIPAL:
  Pipeline de Correção → Refinamento Final → Validação G-10 → Persistência

CARACTERÍSTICAS:
  - Processamento de múltiplas opções (1, 2, 3)
  - Proteção de alimentos proteicos
  - Normalização de gordura implícita
  - Convergência multi-objetivo
  - Tolerância clínica para casos extremos

================================================================================
                     4. PIPELINE DE CORREÇÃO
================================================================================

A pipeline executa até 3 ciclos de correção, cada um com 5 etapas.

--------------------------------------------------------------------------------
ETAPA 1: CALORIAS
--------------------------------------------------------------------------------

  Objetivo: Ajustar calorias totais para range permitido

  REGRA CRÍTICA: NUNCA reduzir proteína para cortar calorias

  SE calorias > max:
    → Reduzir gorduras primeiro
    → Depois reduzir carboidratos
    → NUNCA reduzir alimentos proteicos

  SE calorias < min:
    → Aumentar carboidratos primeiro
    → Depois aumentar proteína

--------------------------------------------------------------------------------
ETAPA 2: PROTEÍNA
--------------------------------------------------------------------------------

  Objetivo: Garantir proteína mínima

  SE proteína < protein.min:
    → Identificar alimentos proteicos (contrib.protein >= 15g/100g)
    → Ordenar por ratio proteína/gordura (maior primeiro)
    → Aumentar porções até atingir mínimo
    → Para CUT: limitar impacto calórico (max 50kcal)

--------------------------------------------------------------------------------
ETAPA 3: CARBOIDRATOS (apenas bulk)
--------------------------------------------------------------------------------

  Objetivo: Garantir carboidratos mínimos para bulk

  SE objective === "bulk" E carbs < carbs.min:
    → Identificar alimentos ricos em carbs (contrib.carbs >= 20g/100g)
    → Aumentar porções respeitando limites de categoria

--------------------------------------------------------------------------------
ETAPA 4: GORDURA
--------------------------------------------------------------------------------

  Objetivo: Reduzir gordura se acima do máximo

  REGRA CRÍTICA: Apenas reduzir gorduras PURAS

  GORDURAS PURAS (podem ser reduzidas):
    → Baixa proteína (<10g/100g) E alta gordura (>20g/100g)
    → Categoria inclui: gordura, oleaginosa, azeite, óleo

  PROTEÇÃO DE PROTEÍNA (v5.5):
    → SE contrib.protein >= 10 E contrib.fat < contrib.protein
    → NÃO REDUZIR (proteína domina gordura)
    
    → SE contrib.fat >= contrib.protein (gordura domina)
    → PODE REDUZIR (ex: oleaginosas, pastas)

--------------------------------------------------------------------------------
ETAPA 4.5: NORMALIZAÇÃO DE GORDURA IMPLÍCITA
--------------------------------------------------------------------------------

  Objetivo: Corrigir excesso de gordura de fontes mistas

  CONDIÇÕES PARA EXECUTAR:
    1. G-10 status === "ALLOW_REBALANCE" (obrigatório)
    2. OU gordura > 110%
    3. OU calorias > 105%
    4. OU (proteína >= 95% E carbs 90-110% E gordura > 100%)

  FONTES MISTAS:
    → fat >= 8g/100g E protein >= 15g/100g
    → OU (fat >= protein E fat >= 20g/100g E oleaginosa)

  ESTRATÉGIA A - Redução de Porção:
    → Ordenar por densidade de gordura
    → Priorizar onde gordura domina proteína
    → Reduzir até 70% para gordura dominante, 40% para outros
    → PROTEÇÃO: Não reduzir se proteína cairia abaixo de 95%
                (90% se gordura domina)

  VALIDAÇÃO CRÍTICA:
    SE após normalização: gordura > 115% OU calorias > 110%
    → STRUCTURALLY_INVALID
    → Retornar imediatamente
    → Ação: "Regenerar plano com fontes proteicas mais magras"

--------------------------------------------------------------------------------
ETAPA 4.6: CARB-FIRST LOGIC (apenas bulk)
--------------------------------------------------------------------------------

  Objetivo: Calorias extras devem vir de carboidratos primeiro

  REGRA CANÔNICA: Em bulk, quem cresce é o carbo

  SE objective === "bulk":
    SE calorias < 95% E carbs < 100%:
      → Calcular calorias faltantes
      → Converter para gramas de carbs (4 kcal/g)
      → Adicionar sem ultrapassar 110% de carbs
      → Gordura só entra quando carbs >= 100%

--------------------------------------------------------------------------------
ETAPA 5: GORDURA - ADICIONAR (opcional, não-cut)
--------------------------------------------------------------------------------

  Objetivo: Completar calorias com gordura se necessário

  APENAS SE: objective !== "cut" E calorias < 95% E carbs >= 100%

  → Adicionar gordura de fontes puras (azeite, oleaginosas)
  → Respeitar limite máximo de gordura

--------------------------------------------------------------------------------
REFINAMENTO FINAL (±1g)
--------------------------------------------------------------------------------

  Após pipeline, executa refinamento de precisão:

  PRECISION = {
    calories: 5,   // ±5 kcal
    protein: 1,    // ±1g
    carbs: 1,      // ±1g
    fat: 1,        // ±1g
  }

  WEIGHTS (priorização):
    calories: 1.0
    protein: 3.0   // Proteína tem peso 3x
    carbs: 1.0
    fat: 1.0

  ALGORITMO:
    → Calcular erro total ponderado
    → Testar ajustes de -5g a +5g por alimento
    → Escolher ajuste que mais reduz erro total
    → Bônus de 50% para ajustes que melhoram proteína em déficit
    → Proteção: não reduzir proteicos se proteína <= 2g acima da meta
    → Máximo 200 iterações

================================================================================
                     5. VALIDAÇÃO FINAL
================================================================================

A validação final é a ÚNICA fonte da verdade para status do plano.

--------------------------------------------------------------------------------
TIPOS DE STATUS
--------------------------------------------------------------------------------

  VALIDATED:
    → Plano atende todos os critérios
    → G-10 PASS ou ALLOW_REBALANCE com normalização

  VALIDATED_WITH_TOLERANCE:
    → Plano atende critérios sob tolerância clínica
    → Gordura entre 110% e 115%

  STRUCTURALLY_INVALID:
    → Plano não pode ser corrigido
    → Hard fail absoluto OU critérios não atendidos

--------------------------------------------------------------------------------
FLUXO DE VALIDAÇÃO
--------------------------------------------------------------------------------

  1. HARD FAIL ABSOLUTO:
     SE calorias > 110% OU gordura > 120%
     → STRUCTURALLY_INVALID

  2. CASO NORMAL (G-10 PASS):
     SE calorias <= 105% 
        E proteína >= 95%
        E carbs >= threshold_por_objetivo
        E gordura <= 110%
     → VALIDATED

  3. CASO AJUSTÁVEL (G-10 ALLOW_REBALANCE):
     SE normalização foi aplicada:
       SE critérios atendidos com gordura <= 115%:
         SE gordura > 110%: VALIDATED_WITH_TOLERANCE
         SENÃO: VALIDATED
       SENÃO: STRUCTURALLY_INVALID
     SENÃO: STRUCTURALLY_INVALID (normalização era obrigatória)

  4. FALHA PADRÃO:
     → STRUCTURALLY_INVALID com razões específicas

--------------------------------------------------------------------------------
STATUS DE RETORNO
--------------------------------------------------------------------------------

  valid:
    → Plano validado E todas opções convergiram

  valid_with_alert:
    → Plano validado com tolerância
    → OU algumas opções não convergiram

  error:
    → Plano estruturalmente inválido
    → OU validação final falhou

  structurally_invalid:
    → Plano precisa ser regenerado
    → Contém structural_issue com detalhes
